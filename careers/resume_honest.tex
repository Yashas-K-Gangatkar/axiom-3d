\section*{Featured Project: AXIOM --- Binary Substring Graph for Zero-Error Retrieval}
\href{https://github.com/Yashas-K-Gangatkar/axiom-3d}{\textbf{github.com/Yashas-K-Gangatkar/axiom-3d}} $\cdot$ October 2026

\textit{Independent research project on exact-match retrieval. Designed the architecture; implementation was developed with AI assistance.}

\textbf{My role (what I can defend in an interview):}
\begin{itemize}
\item Designed the three-layer architecture: V1 prefix trie, V2 LZ77 macro graph, V3.1 LOUDS succinct trie
\item Defined the honest measurement methodology: real Gutenberg text at 1/10/100\,MB, 5 adversarial fake queries per size
\item Specified the trade-offs: 212$\times$ bloat in V1, 94\% reduction in V3.1, $O(N \cdot L)$ substring search complexity
\item Wrote the IEEE-format paper draft (8 pages, 14 references), including the honest limitations section
\item Drove the research direction: zero-error verification as a complement to ANN-based retrieval in RAG pipelines
\end{itemize}

\textbf{What I am currently learning to fully own:}
\begin{itemize}
\item Rust ownership, borrowing, and lifetimes (to read and modify the implementation)
\item LOUDS rank/select implementation details (to extend V3.1)
\item Ukkonen's suffix tree construction (the next planned upgrade)
\end{itemize}

\textbf{Honest limitations of the project:}
\begin{itemize}
\item V2 is 38$\times$ worse than \texttt{xz -9} on compression ratio (no entropy coding)
\item Substring search is $O(N \cdot L)$, not $O(L)$ --- suffix-tree upgrade is future work
\item Single-threaded build (no parallelism yet)
\end{itemize}
